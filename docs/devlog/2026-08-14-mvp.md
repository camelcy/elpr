# 开发日记｜2026-08-14｜MVP

## 背景与目标

目标是交付一个完全本地运行的 MVP：将 Zotero 中的文字高亮和图片批注，增量同步到 Obsidian 的 Excalidraw 画布；同时让用户能够从 Zotero 创建、打开并关联画布，并从画布内容回跳到对应文献或批注。

该目录没有 Git 元数据，因此本日志以当天文件修改时间、代码实现、自动化测试和本地服务状态为依据。

## 时间线与完成内容

### 15:07–15:20｜建立本地运行基础

搭建 Python 后端、Obsidian 插件和构建配置，并补齐服务启动、停止、安装、卸载和 Zotero 社区插件更新脚本。架构选择通过 Zotero 本地 HTTP API 读取批注，而不是直接读取 Zotero SQLite；这样可避免直接操作 Zotero 数据库，并保持整个流程不依赖云端服务或外部 AI。

### 17:12–18:03｜实现配置、持久化状态与画布关联

实现服务配置、同步状态存储和“Zotero 父条目 key → Excalidraw 相对路径”的持久化映射。Obsidian 端增加服务客户端与设置页面，支持配置自动同步和文献画布目录。与此同时补齐 Zotero XPI 的构建流程，为 Zotero 侧的一键创建/打开/关联画布提供交付基础。

### 20:56–21:17｜完成增量同步状态机和后端接口

实现 Zotero 批注轮询、排序、去重和增量状态管理，处理文字高亮与图片批注。图片使用 Zotero PDF 坐标、PDF CropBox 与页面旋转信息，通过 PyMuPDF 在本地裁剪。

同步采用“保留用户编辑”的策略：已导入内容根据 annotation key 识别，不因文本被用户编辑而重复导入；源内容变更只提示“source updated”，不覆写画布中的位置、缩放和文本；源批注被删除时只标记 `source_missing`，不删画布元素。未关联画布的批注保持 `pending`，在文献完成绑定后再处理。服务还提供健康检查与状态接口，并记录不含完整批注正文的脱敏日志。

### 21:35–22:06｜完善 Excalidraw 生成与 Zotero/Obsidian 交互

实现画布管理和 Excalidraw 写入逻辑。文字批注拆为“评论/翻译”和“原文”两个独立块，并支持按设置调整显示顺序；内容按 PDF 物理页码和排序索引排列，文本在画布中按视觉宽度换行。所有同步元素都携带 annotation key 元数据，文献标题和批注均包含回跳 Zotero 的链接。

完善 Zotero 侧交互：可从文献或 PDF 创建、打开并绑定 Excalidraw 画布，在条目详情中显示关联状态与路径；首次创建或打开画布时补充可回跳 Zotero 的文献标题。Obsidian 端支持将目标文件作为 Excalidraw 画布打开，并提供专注模式切换。

### 22:09–22:14｜联调与交付文档

完成本地服务联调，补充 README 中的安装、配置、使用、故障排查和已知限制说明，并提供测试映射示例，避免测试过程影响真实文献画布。

## 关键决策

- 使用 annotation key 作为同步身份，而非可编辑文本，保证用户修改文本后仍能稳定去重。
- 同步只添加或标记状态，不重写用户编辑过的画布内容，优先保护人工整理成果。
- 将“未映射”“源更新”“源缺失”建模为明确状态，而不是静默丢弃或删除内容，以便后续处理和排查。
- 图片裁剪在本地完成，保持数据处理边界清晰。
