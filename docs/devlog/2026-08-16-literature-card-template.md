# 开发日记｜2026-08-16｜文献卡片模板外置

## 背景与目标

昨天已经打通 Zotero 文献条目、Obsidian Literature 文献卡片和 Excalidraw 画布，但新卡片的完整 Markdown 结构仍以内嵌字符串保存在 Python 代码中。今天的目标是把这部分内容提取为可直接编辑的 Markdown 模板，让正文标题和固定字段可以独立调整，同时继续保证 Zotero 元数据、机构信息、日期与画布链接被安全写入。

本日志以 2026-08-16 当天的 Git 提交、当前工作区、自动化测试和构建结果为依据。整理前工作区无未提交改动；本地服务当时未运行，因此没有把实时接口或真实 Zotero 条目操作列为已验证。

## 时间线与完成内容

### 00:15｜归档前一日开发日记

将 8 月 15 日“发布流程、文献卡片与机构元数据”开发日记及索引提交到项目文档，使项目内 `docs/devlog` 与 Obsidian 中的阅读副本保持对应。

### 11:30–23:25｜将文献卡片结构提取为 Markdown 模板

新增 `templates/literature-card.md`，把原先写在 `backend/literature.py` 中的 frontmatter、摘要 callout、研究背景、问题—方法—结果、局限性、文献联系、原文与画布链接等固定结构迁移到独立文件。模板保留标题、作者、机构、年份、引用键、DOI、Zotero key、Zotero 链接、Excalidraw 链接、创建/修改日期等 13 个动态占位符。

`LiteratureCardStore` 默认使用项目内模板，并支持在测试或其他调用场景传入自定义模板路径。服务在每次新建文献卡片时重新读取模板，因此修改模板并保存后，不需要重新构建插件；下一张新卡片会直接采用新内容。已有卡片仍沿用原有的幂等与保守更新策略，不会因模板变化而重写正文或已填写字段。

为防止模板编辑导致静默丢失元数据，生成前会检查全部必需占位符；模板文件无法读取或缺少占位符时会明确报错，而不是生成结构不完整的卡片。动态内容继续使用既有 YAML 转义、待填写占位、原子写入和文件名冲突处理逻辑。

同步调整文献卡片测试断言，使其覆盖新的正文标题和摘要结构，并在 README 中明确两个模板位置的职责：项目内 `templates/literature-card.md` 是程序实际读取的唯一来源；Obsidian 中 `40 - Obsidian/模板/文献卡片模板.md` 只是便于查看和编辑的副本，两者目前不会自动互相覆盖。

## 关键决策

- 以项目内 `templates/literature-card.md` 作为运行时唯一模板来源，避免项目模板与 Obsidian 模板副本之间出现不明确的覆盖关系。
- 每次创建新卡片时从磁盘读取模板，而不是在服务启动时缓存，使正文结构调整可以立即影响后续新卡片。
- 将动态值限制在明确列出的双花括号占位符中，继续由 Python 负责 YAML 转义、机构列表和链接生成；模板只负责结构与固定文字。
- 必需占位符缺失时中止创建并返回明确错误，避免生成看似成功但元数据不完整的文献卡片。
- 模板变化只影响新建卡片；已有卡片继续保护用户正文和非空字段，不做批量迁移。
