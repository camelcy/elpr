# 开发日记

本目录记录每次开发的背景、关键决策、验证情况和遗留事项。它服务于开发者复盘；面向使用者的功能变化写入上一级的 [CHANGELOG.md](../CHANGELOG.md)。

## 每晚规则

在当天最后一次开发结束后，执行一次开发日记整理：

1. 先收集当天证据：Git 提交与未提交改动、当天修改的文件、测试/构建结果，以及运行日志或接口状态（如适用）。没有 Git 仓库时，明确注明以文件修改时间和实现内容为依据。
2. 新建 `YYYY-MM-DD-<topic>.md`。`<topic>` 使用当天工作的核心主题，例如 `mvp`、`sync-retry` 或 `settings`。
3. 日记必须区分事实与判断：只把已检查到的内容写成“完成”；未验证内容要注明验证缺口；不要记录密钥、完整用户数据或私密日志。
4. 以时间线组织“做了什么、为什么这样做、影响了什么”，而不是只罗列文件名。
5. 若当天有用户可见的功能、配置、兼容性或已知限制变化，同步更新 `docs/CHANGELOG.md`；纯重构、测试和内部脚本无需加入变更记录。
6. 在本 README 的“索引”中补充新日志链接，最新记录置顶。
7. 将完成后的日记原样同步到 Obsidian 库 `D:\\Obsidian\\Steins Gate\\70 - Ai\\elpr`。项目内 `docs/devlog/` 是维护索引和版本记录的源位置；Obsidian 副本只存放可阅读的日记文件。
