# 开发日记｜2026-08-15｜发布流程、文献卡片与机构元数据

## 背景与目标

在前一天完成本地 MVP 后，今天的目标是把项目纳入 Git 与可发布流程，统一 Zotero 文献画布和同步内容的视觉规范，并打通“Zotero 条目 → Obsidian Literature 文献卡片 → Excalidraw 画布”的使用路径。后半段进一步补齐文献卡片的 DOI 和作者机构元数据，使新卡片能够在网络服务可用时自动获得机构中文名，在离线、限流或数据缺失时仍可安全创建。

本日志以 2026-08-15 当天的 Git 提交、当前工作区、自动化测试、构建产物和本地服务接口为依据。记录整理前后工作区均无未提交改动；运行时数据和完整服务日志未写入本文。

## 时间线与完成内容

### 00:03–00:14｜导入 Git 并接通 Zotero 自动更新基础

将前一天的 MVP 完整导入 Git，纳入后端、Obsidian 插件、Zotero 插件、测试、脚本、示例配置和开发文档。随后为 Zotero 插件清单增加远程更新地址，建立 `zotero-updates.json`，并合并首个自动更新相关分支，为后续通过 GitHub Release 分发 XPI 奠定基础。

同时整理本地运行文件的忽略规则和测试映射示例，避免本机配置、状态数据与真实文献映射进入版本库。

### 14:57–15:05｜建立可手动触发的 Zotero 发布流程

新增 Windows GitHub Actions 发布工作流。发布只能从 `main` 手动触发；流程会校验版本、安装依赖、运行完整测试、构建 XPI、创建或更新同版本 GitHub Release，并将带 SHA-256 校验值的自动更新记录提交回 `main`。普通代码推送不会自动发布，避免未准备完成的版本被直接分发。

修复云端构建时 `dist` 目录尚不存在导致 XPI 打包失败的问题，并完成 Zotero 0.1.7 的发布记录。

### 15:40–15:53｜统一文献画布模板与同步文字样式

统一新建 Excalidraw 文献画布：标题保持单行显示，下方使用“主要工作”“解决问题/重要进展”“优化方向”三个彩色整理区。同步进入画布的原文与评论/翻译统一采用支持中英文的手写字体和 Excalidraw M 号字号，使自动生成内容与画布模板保持一致。

实现仍遵循保护既有内容的原则：只为新建空白画布生成完整模板；已有非空画布只补充缺失标题，不改写用户现有布局。

### 19:00–19:06｜打通 Zotero 文献卡片与 Literature Base

新增后端文献卡片管理模块和服务接口，并扩展 Zotero 插件交互。用户现在可以从 Zotero 右键菜单或条目详情区创建、打开文献卡片；卡片按 `zotero_key` 识别，写入 Literature Base 可直接筛选的 frontmatter，并关联已有 Excalidraw 画布。

卡片创建采用幂等和保守更新策略：重复请求不会重复创建；文件名冲突时追加条目 key；已有卡片中的用户字段、正文和非空机器字段保持不变。随后修复文献画布 wikilink 在 Python 3.11 下的兼容性，并准备 Zotero 0.1.8。

### 21:31–21:42｜完善 DOI、占位符与 Zotero 0.1.9

将 DOI 规范化为可点击的 `https://doi.org/...` 链接，并统一引用键、作者、年份、机构和画布映射等缺失字段的“待填写”语义，保证即使 Zotero 元数据不完整，也能生成合法且结构稳定的 YAML。

补充 Zotero 插件和后端回归测试后，完成 Zotero 0.1.9 的版本与自动更新记录。

### 22:15–23:14｜提取并翻译作者所属机构

新增机构元数据模块。创建新文献卡片时，服务可按 DOI 查询 OpenAlex，从作者顺序中选取首次出现的第一单位，并将其写入 `institutions` YAML 列表。中文名称依次利用人工映射、Wikidata 中文标签和可选的 OpenAI-compatible 翻译服务；查询与翻译结果保存在本地缓存中，网络超时、404、429、无 DOI 或无机构时均降级为“待填写”，不阻断卡片创建。

为避免重复维护译名，当所有在线翻译来源都无法给出中文结果时，服务会只读扫描既有文献卡片：只有同一英文机构存在唯一一致的中文译名时，才复用该译名并写入人工映射；存在冲突则保持“待填写”。API 密钥只从配置指定的环境变量读取，不写入配置文件或缓存。

同步更新示例配置、README、变更记录、测试夹具和版本文件，将当前开发版本整理为 Obsidian 0.1.3 / Zotero 0.1.10。

### 23:22｜完整验证与本地打包

运行 TypeScript 类型检查、全部 TypeScript/Python 测试和两端生产构建。Obsidian 插件生成 `dist/main.js`，Zotero 插件重新生成 `dist/zotero-excalidraw-canvas-0.1.10.xpi`。本地服务健康检查返回正常，并能通过汇总接口读取同步状态。

## 关键决策

- Zotero 发布采用“从 `main` 手动触发”的 GitHub Actions，而不是随普通推送自动发布；发布门槛包含测试、打包、Release 上传和更新清单回写。
- 文献卡片以 frontmatter 中的 `zotero_key` 作为身份，不依赖可变文件名；创建与更新均优先保留用户已经填写的字段和正文。
- Literature Base 继续依靠目录与 `type: literature` 自动收录，新功能不直接改写 Base 配置，降低对现有 Obsidian 工作区的侵入。
- 每篇卡片只记录按作者顺序首次出现的第一单位，避免完整机构列表给日常阅读卡片带来噪声。
- 机构中文名采用“人工映射优先、公开数据和可选翻译服务补充、失败安全降级”的策略；仅在既有卡片译名唯一一致时自动学习，避免把冲突译名固化到映射表。
- 机构查询只在首次创建卡片时运行；打开已有卡片不访问网络，也不覆盖用户内容。
